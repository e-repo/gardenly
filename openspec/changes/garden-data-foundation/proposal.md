# Proposal

## Why

Страницы «Сегодня» и «Мой сад» пока являются заглушками, а общего контракта доступа к данным ещё нет. Нужен единый read-only фундамент, чтобы обе страницы получали согласованные мок-данные через `GardenRepository` и не создавали независимые источники состояния.

## What Changes

- Определить предметные типы растений, культур, задач, настроек и статичной погоды, необходимые первым экранам MVP.
- Зафиксировать глобальный backend-frontend контракт моментов времени RFC 3339 в UTC с точностью до секунд и календарных дат `YYYY-MM-DD`, не реализуя backend.
- Добавить read-only контракт `GardenRepository` для получения сада, конкретного растения, задач дня, задач растения, справочника культур, настроек и погоды.
- Создать mock-реализацию с четырьмя растениями из продуктового видения, справочником культур, задачами с объяснениями и регионом «Подмосковье».
- Подключить реализацию через composition root Nuxt, не импортируя `data/` в UI.
- Добавить unit-тесты контракта mock-реализации и границы чтения задач на текущую локальную дату.
- Не добавлять изменение задач или растений, Pinia stores, localStorage, генератор сезонных правил, backend и новые элементы страниц.

## Capabilities

### New Capabilities

- `garden-data-access`: единый доступ UI и предметных модулей к данным сада через репозиторий с локальной mock-реализацией.

### Modified Capabilities

Нет.

## Impact

- Появятся `app/domain/`, `app/data/` и Nuxt composition root для внедрения репозитория.
- Мок-данные будут расположены в `app/data/` отдельно от тестовых фикстур.
- Изменятся только инфраструктура данных и её unit-тесты; видимое поведение текущих страниц останется прежним.
- Глобальные правила представления дат и времени будут добавлены в `openspec/constitution.md`.
- Следующие changes `garden-list` и `today-overview` смогут использовать контракт без обращения к mock-данным напрямую.

# Design

## Context

После `add-plant` существуют форма создания участка, `usePlotsStore` для обзора и `usePlotDetailsStore` для деталей. `MockGardenRepository` хранит рабочий список участков и возвращает независимые снимки. Мотивация и объём — в [proposal.md](proposal.md), поведение — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Использовать один контракт обновления для mock и будущего backend.
- Локально обновлять уже загруженный обзор без полной перезагрузки.
- Сохранять идентификатор, порядок и погодный контекст участка.
- Явно отделять ошибку чтения от неизвестного участка.

**Non-Goals:**

- Не менять структуру погодных данных, уведомления и координаты.
- Не добавлять удаление, soft delete, корзину или восстановление: рабочее удаление появится отдельным `delete-plot`.
- Не связывать store обзора и деталей дополнительными зависимостями.

## Decisions

### Контракт обновления

В `app/domain/garden.ts` добавляются:

```ts
interface UpdatePlotInput {
  name: string;
  locationLabel: string;
}

updatePlot(id: string, input: UpdatePlotInput): Promise<Plot>;
```

Отдельный `UpdatePlotInput` фиксирует допустимые поля и не допускает смену `id` через `Partial<Plot>`. `updatePlot()` использует общий с `createPlot()` приватный helper нормализации и проверки названия и локации. Все проверки выполняются до записи; порядок участка и идентификатор сохраняются, возвращается `structuredClone`-снимок.

### Store обзора

`usePlotsStore` получает `updatePlot(id, input)` с `isUpdating`, `hasUpdateError` и результатом `boolean`. Повторный вызов во время запроса возвращает `false` без нового обращения к репозиторию.

После обновления store заменяет участок с тем же `id` на текущей позиции и сохраняет `weatherByPlotId`. Если обзор ещё не загружен, локальный список не пополняется искусственно: последующий `loadGarden()` получит актуальный порядок из репозитория. При ошибке список и погода не меняются.

Существующий `onMounted` перечитывает детали при возврате из `/plots/:plotId/edit`, а обзор перечитывается при следующем открытии `/garden`. Локальное обновление устраняет устаревшую карточку до этого чтения, а повторное чтение покрывает прямой вход в форму, когда обзор не был загружен. Дополнительная связь между store не вводится.

### Форма и маршрут

Новый `app/modules/plots/plot-edit/components/PlotEditForm.vue` принимает `plotId`, загружает участок через `getPlot()` и заполняет локальные `name` и `locationLabel`. Он различает loading, load error и not-found; форма отображается только для существующего участка. Страница `app/pages/plots/[plotId]/edit.vue` только извлекает параметр и компонует заголовок и форму.

Поля и валидация повторяют установленный паттерн `PlotCreateForm.vue`, но submit вызывает `updatePlot`. При успехе и отмене выполняется `router.push(`/plots/${plotId}`)`. При ошибке значения остаются в локальных полях.

### Точка входа и действия формы

В заголовок `PlotDetailsContent.vue` добавляется icon-кнопка `mdi-pencil-outline` с локализованным accessible name и маршрутом `/plots/${store.plot.id}/edit`. Карточки обзора не получают дополнительных действий и остаются переходами к деталям.

На экране редактирования размещаются только сохранение и отмена. Кнопка удаления не добавляется до `delete-plot`, чтобы не создавать неработающий control. Все строки находятся в `pages.editPlot` и связанных ключах `ru.json`. Используются MDI, стандартная тема и скругления Vuetify; действия имеют touch-область не меньше 44 px.

### Тестирование

- Repository-тесты `updatePlot`: нормализация, сохранение `id` и порядка, независимость snapshot, неизвестный участок и пустые значения без изменений.
- Store-тесты: замена карточки без изменения порядка и погоды, прямой вход без предзаполненного списка, ошибка и блокировка повторного обновления.
- Компонентные тесты: переход из деталей, предзаполнение, loading/error/not-found, валидация, сохранение и возврат, отмена и ошибка с сохранением значений, мобильные действия без emoji и кнопки удаления.

## Risks / Trade-offs

- [Повторные `loadGarden` и `loadPlotDetails` после возврата дублируют локальное обновление] → Локальные mock-запросы дёшевы, а повторное чтение поддерживает прямой вход в форму и не требует связи между store.
- [Дублирование двух полей и валидации с формой создания] → Повторяется установленный паттерн без более широкого рефакторинга; общий код можно выделить при появлении дополнительных сценариев.

## Migration Plan

1. Завершить `add-plant` и применять изменение к стабильной структуре `modules/plots`.
2. Добавить контракт, mock-обновление и repository-тесты.
3. Расширить `usePlotsStore` и покрыть состояние обзора тестами.
4. Добавить форму, маршрут, действие редактирования и i18n вместе с компонентными тестами.
5. Прогнать quality gates и выполнить Chrome-сценарий на ширине 390 px: изменить название и локацию, проверить детали и карточку; проверить валидацию, отмену, ошибки, неизвестный участок и отсутствие кнопки удаления.

Откат удаляет новый маршрут, форму, действие редактирования и метод обновления. Mock-изменения существуют только в памяти; миграция данных не требуется.

# Design

## Context

Проект использует npm с зафиксированным `package-lock.json`. Актуальные версии непосредственных зависимостей уже установлены, а замечания относятся к transitivным `deepmerge@4.3.1`, `glob@13.0.7` и `minimatch@10.2.6`. Автоматическое исправление npm предлагает мажорные откаты верхнеуровневых пакетов, которые нарушат текущую конфигурацию.

## Goals / Non-Goals

**Goals:**

- Получить нулевой результат полного и production npm audit без изменения принятого стека.
- Зафиксировать минимальное и воспроизводимое дерево зависимостей.
- Сделать audit неизменной частью локальных и будущих CI quality gates.

**Non-Goals:**

- Не обновлять непосредственные зависимости, не участвующие в устранении замечаний.
- Не подавлять advisories, не понижать порог severity и не настраивать исключения.
- Не менять исходный код и поведение приложения.

## Decisions

### Точечные npm overrides вместо `npm audit fix --force`

В `package.json` зафиксировать только уязвимые transitivные пакеты:

- `deepmerge: 4.1.2` — версия до появления prototype poisoning в диапазоне `>=4.2.0`;
- `glob: 14.0.4` — версия после уязвимого диапазона `9.0.0–14.0.1`;
- `minimatch: 11.0.5` — версия после уязвимого диапазона `7.0.0–11.0.0`.

Overrides выбраны потому, что непосредственные родительские пакеты ещё не обновили свои диапазоны. Они должны быть проверены всеми quality gates и браузерным smoke-сценарием. Если выбранная версия нарушает совместимость, реализация останавливается, а design пересматривается; нельзя оставить частичный override ради нулевого отчёта.

Альтернатива с `--force` отклонена: npm выбирает старые Nuxt 4.1.3, ESLint 9 и Vue Test Utils 2.4 вместо устранения проблем в текущем стеке. Ожидание upstream-обновлений отклонено, потому что безопасные версии `glob` и `minimatch` уже доступны, а для `deepmerge` существует незатронутая совместимая линия.

### Две явные команды audit

Добавить:

```text
audit = npm audit --audit-level=low
audit:production = npm audit --omit=dev --audit-level=low
```

Явный `--audit-level=low` делает любое известное замечание блокирующим. Проверяющие команды только читают дерево и не выполняют автоисправлений. Production audit отдельно показывает состояние поставляемых зависимостей, а полный audit дополнительно контролирует инструменты разработки.

### Явное изменение конституции и документации

Добавить обе команды в раздел обязательных quality gates конституции. Указать, что любое известное замечание блокирует завершение и archive, а исправления выполняются отдельно от проверяющих команд без `--force`. В `README.md` добавить те же команды и краткий порядок разбора `npm audit`: сначала отчёт, затем совместимое исправление, затем полный набор gates.

Будущий CI будет вызывать те же npm scripts; сам CI-пайплайн в этот change не входит.

## Risks / Trade-offs

- [Мажорные overrides могут нарушить API transitivных зависимостей] → Проверить установку с чистым lockfile, lint, typecheck, тесты, production build и запуск приложения; при ошибке откатить override и пересмотреть design.
- [Откат `deepmerge` оставляет старую версию дольше необходимого] → Не скрывать override, пересматривать его при обновлении родительских пакетов и удалять после появления исправленной совместимой версии.
- [Новые advisories могут блокировать не связанный по смыслу change] → Принять это как следствие нулевого порога; устранять замечания отдельным проверенным изменением без скрытых исключений.
- [Два audit частично дублируют работу] → Сохранить отдельный production-результат ради явной диагностики; команды быстрые и используют одинаковый lockfile.

## Migration Plan

1. Добавить overrides и npm scripts, выполнить `npm install` для пересборки lockfile.
2. Проверить фактические версии через `npm ls` и оба отчёта audit.
3. Выполнить остальные quality gates и smoke-проверку приложения.
4. Обновить конституцию и README только после подтверждения совместимости.
5. Для отката удалить overrides, восстановить прежний lockfile и повторить установку; миграция данных не требуется.

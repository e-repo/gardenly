# Design

## Context

Все компоненты `app/modules/plots/components/` подключаются явными импортами через `~/`; auto-import компонентов модуля не используется. Store обзора также владеет созданием участка: `PlotCreateForm` вызывает `usePlotsStore().createPlot`. Детальный экран имеет независимый `usePlotDetailsStore`. Существующие unit-тесты импортируют компоненты и stores по текущим путям.

## Goals / Non-Goals

**Goals:**

- Сгруппировать файлы по экранам, сохранив текущие границы ответственности и явные зависимости.
- Сделать перемещение механическим: изменяются только пути файлов и импорты.

**Non-Goals:**

- Не разделять и не переименовывать stores, экспортируемые функции, компоненты и их props.
- Не менять поведение, маршруты, репозиторий, тестовые сценарии и структуру каталога `test/`.
- Не добавлять barrel-файлы `index.ts` или новый публичный API модуля.

## Decisions

### Каталог фичи соответствует экрану

`garden/` получает пять компонентов обзора и `store.ts`; `plot-details/` — шесть компонентов детального экрана и бывший `plot-details-store.ts` под именем `store.ts`; `plot-create/` — `PlotCreateForm.vue`. Компоненты переносятся целиком, без одновременного редактирования их логики.

Альтернатива с плоской структурой отклонена: она не решает проблему роста модуля. Более глубокая иерархия с отдельными слоями внутри каждой фичи избыточна для текущего числа файлов.

### Stores перемещаются вместе с основными потребителями

Экспорты `usePlotsStore` и `usePlotDetailsStore`, а также Pinia-ID `plots` и `plot-details` остаются прежними. `PlotCreateForm` после перемещения импортирует `usePlotsStore` из `~/modules/plots/garden/store`: это сохраняет существующее обновление списка участков после создания. Вынос общего store в корень или создание отдельного store формы потребовал бы изменения ответственности и не относится к структурной чистке.

### Только действительно общие helpers остаются в корне модуля

`weather.ts` используется обзором и деталями, а `plants.ts` содержит общие правила категорий и возраста посадок. Они остаются в `app/modules/plots/`; их реализации и экспорты не меняются. Компоненты импортируют helpers и stores прямыми путями через `~/`, без re-export через `index.ts`.

### Импорты обновляются атомарно с перемещениями

Внутри фич используются прямые абсолютные пути к новым расположениям, как и сейчас. Страницы и существующие тесты получают только новые import-path; имена и содержимое тестовых файлов сохраняются. Старые каталоги и файлы не остаются как прослойки совместимости.

## Risks / Trade-offs

- [Пропущенный импорт после перемещения] → Поиск старых путей, затем `typecheck`, unit-тесты и build.
- [Случайное изменение поведения при ручном переносе] → Перемещать файлы без правки логики; существующие тесты служат регрессионной проверкой.
- [Зависимость `plot-create` от `garden/store.ts` выглядит менее изолированно] → Принять её как отражение текущей общей ответственности store; разделение рассматривать только отдельным изменением при реальной необходимости.

## Migration Plan

Все перемещения и правки импортов выполняются одним рефакторингом. Миграция данных и runtime-совместимость не требуются; откат выполняется обратным перемещением через откат коммита.

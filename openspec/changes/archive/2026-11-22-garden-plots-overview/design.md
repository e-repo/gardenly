# Design

## Context

После `plots-data-foundation` репозиторий предоставляет `Plot`, участки и текущую погоду по `plotId`. Существующий модуль Today использует прежние дневные методы и `Culture.emoji`, а нижняя навигация ссылается на старую модель разделов. Требования находятся в `specs/`; мотивация — в [proposal.md](proposal.md).

## Goals / Non-Goals

**Goals:**

- Собрать завершённый сценарий просмотра и создания участка без неработающего CTA.
- Перевести shell на новые разделы и удалить прежнюю дневную модель и emoji.
- Сохранить страницы композицией, бизнес-логику в модуле `plots`, а доступ к данным — через `GardenRepository`.

**Non-Goals:**

- Не сохранять созданные участки в localStorage или backend после полной перезагрузки.
- Не делать карточки переходами к ещё не реализованным деталям участка.
- Не добавлять редактирование, уведомления, рекламу и содержимое `/tasks` или `/help`.
- Не переносить MDI-имена в предметный `Culture` или mock-данные.

## Decisions

### Контракт профиля и создания участка

Добавить:

```ts
interface UserProfile {
  id: string;
  displayName: string;
}

interface NewPlotInput {
  name: string;
  locationLabel: string;
}

getProfile(): Promise<UserProfile>;
createPlot(input: NewPlotInput): Promise<Plot>;
```

`getProfile()` читает отдельный mock-профиль. Реальная аутентификация не моделируется: экран получает уже аутентифицированное состояние через тот же репозиторий.

`MockGardenRepository` хранит рабочий список участков в памяти экземпляра. `createPlot()`:

- выполняет `trim()` для названия и локации;
- отклоняет пустые значения и не меняет состояние;
- создаёт уникальный человекочитаемый mock-ID через монотонный счётчик экземпляра;
- добавляет участок в конец и возвращает независимый snapshot.

Счётчик выбран вместо случайного UUID для воспроизводимых mock-тестов; backend-представление остаётся деталью будущей HTTP-реализации. Погода нового участка отсутствует, поэтому `getCurrentWeather()` возвращает `null`.

### Модуль `plots` и состояние

В `app/modules/plots/` разместить:

- `store.ts` — профиль, участки, `weatherByPlotId`, флаги чтения и создания;
- `weather.ts` — явное отображение `WeatherForecast.condition` в MDI-иконки;
- `components/GardenOverview.vue` — профиль, CTA, список и состояния чтения;
- `components/PlotCard.vue` — название, локация и погода одного участка;
- `components/PlotCreateForm.vue` — форма, валидация, отправка и отмена.

`loadGarden()` сначала параллельно запрашивает профиль и участки, затем параллельно погоду каждого участка. Присваивание результата происходит целиком после всех запросов. Любой отказ очищает набор и включает ошибку без частичного списка.

`createPlot()` в store вызывает репозиторий, добавляет возвращённый участок локально и устанавливает для него `weatherByPlotId[id] = null`. Повторная загрузка списка после создания не требуется. Состояние чтения и создание разделены: ошибка создания не скрывает существующий список и не очищает введённые поля.

Маршрут и вычисляемые карточки не дублируются в Pinia.

### Композиция экранов и форма

`app/pages/garden.vue` содержит заголовок и `<GardenOverview />`. `app/pages/plots/new.vue` содержит заголовок и `<PlotCreateForm />`.

CTA — блочная `v-btn` цвета `primary` с MDI-иконкой добавления и увеличенной высотой. Она ведёт на `/plots/new` через роутер. Карточка участка остаётся некликабельной: `to`, click-handler, редактирование и колокольчик отсутствуют.

Форма использует нативные labels/i18n, `v-text-field` и две кнопки: создать и отменить. Клиентская проверка не даёт отправить пустые строки, а репозиторий повторно проверяет контракт. Во время запроса submit блокируется. После успеха выполняется `router.push('/garden')`; отмена возвращает на тот же маршрут без вызова репозитория.

Новый участок отображает локализованное «Погода пока недоступна». Значения погоды другого участка не подставляются.

### Shell и удаление прежней модели

`AppBottomNavigation` получает пункты:

- `/garden` — «Мой сад», MDI-иконка участка;
- `/tasks` — «Задачи», MDI-иконка списка;
- `/help` — «Помощь», MDI-иконка справки.

Добавляются страницы `/tasks` и `/help` только с локализованными заголовками, без действий-заглушек. Настройки доступны через MDI-иконку в профиле и сохраняют `/settings`. `app/pages/index.vue` выполняет только `navigateTo('/garden')`.

Удаляются `app/modules/today/`, связанные тесты, `Culture.emoji` и значения emoji из каталога. Новые компоненты используют только `<v-icon>` с MDI-именами. Текстовые emoji в i18n и mock-данных не добавляются.

Артефакты `today-overview` и `garden-list` удаляются как superseded, а не архивируются. В `docs/personal-agronom-mvp.md` отдельный `add-plot` объединяется с `garden-plots-overview`, а упоминание emoji в каталоге заменяется правилом MDI-иконок.

### Тестирование

Repository-тесты проверяют профиль, нормализацию, уникальность и чтение созданного участка, ошибки пустых значений, отсутствие погоды и независимость snapshots, а также отсутствие `Culture.emoji`.

Store-тесты проверяют успех, пустой список, отказ каждого необходимого запроса, создание и его ошибку без потери текущего состояния.

Компонентные тесты покрывают профиль, две карточки и разную погоду, fallback без погоды, empty/loading/error, CTA, валидацию, блокировку submit, успешное создание, отмену и сохранение введённых данных при ошибке. Отдельно проверяется отсутствие emoji и неподдерживаемых controls.

Тесты нижней навигации обновляются для трёх новых маршрутов и активного пункта.

## Risks / Trade-offs

- [Созданный участок исчезает после полной перезагрузки] → Это явное ограничение mock-этапа; постоянное хранение появляется через backend-реализацию без изменения сценария UI.
- [Погода загружается отдельным запросом для каждого участка] → Запросы выполняются параллельно, а атомарное состояние не показывает частичный набор; batch-метод добавляется только при реальной необходимости.
- [Страницы задач и помощи пока содержат только заголовки] → Навигация уже работает, но никаких действий-заглушек на этих страницах нет; содержимое добавляют отдельные changes.
- [Удаление `Culture.emoji` ломает прежние потребители] → Модуль Today и его тесты удаляются в том же change, поиск подтверждает отсутствие оставшихся обращений.

## Migration Plan

1. Применить `plots-data-foundation` и подтвердить наличие участочного контракта.
2. Добавить профиль и `createPlot()` с repository/store-тестами.
3. Заменить shell и удалить Today и emoji.
4. Собрать список и форму создания, обновить продуктовый план и удалить superseded-артефакты.
5. Прогнать quality gates и выполнить Chrome-сценарий: открыть `/`, создать участок, увидеть его в списке и проверить новую навигацию.

Откат восстанавливает прежние страницы, модуль Today и контракт каталога; созданные в памяти участки исчезают при перезапуске и не требуют миграции данных.

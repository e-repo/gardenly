# Spec Delta

## Purpose

Позволяет пользователю добавить посадку в выбранный участок через завершённый мобильный сценарий без неработающих действий и увидеть её в составе участка.

## ADDED Requirements

### Requirement: Переход к добавлению посадки

Детальный экран участка SHALL предоставлять заметное действие «Добавить растение», открывающее форму `/plots/:plotId/plants/new` без полной перезагрузки страницы.

#### Scenario: Пользователь добавляет посадку

- **WHEN** пользователь выбирает «Добавить растение» на экране `/plots/dacha`
- **THEN** приложение открывает форму добавления посадки для участка «Дача» без полной перезагрузки страницы

### Requirement: Поля новой посадки

Форма SHALL содержать культуру, сорт, год посадки, место, количество и название. Культура SHALL быть обязательной и выбираться из общего каталога с поиском; произвольные культуры MUST NOT создаваться. Сорт SHALL быть обязательным и выбираться строго из `commonVarieties` выбранной культуры без свободного ввода. Год SHALL быть обязательным. Место, количество и название необязательны; количество по умолчанию равно 1.

#### Scenario: Выбор культуры и сорта

- **WHEN** пользователь выбирает культуру «Яблоня»
- **THEN** список сортов предлагает только распространённые сорта яблони, и свободный ввод сорта недоступен

#### Scenario: Поиск культуры

- **WHEN** пользователь вводит часть названия в поле культуры
- **THEN** список каталога сужается до подходящих культур без создания новых значений

### Requirement: Проверка данных новой посадки

Форма SHALL требовать выбранные культуру и сорт, заполненный целый год посадки не позднее текущего и целое количество не меньше 1; строковые значения SHALL очищаться от крайних пробелов. Заполненное пользовательское название после очистки SHALL содержать от 3 до 200 символов, пустое название допустимо. Создание с нарушенными правилами MUST NOT выполняться.

#### Scenario: Обязательные поля не заполнены

- **WHEN** пользователь отправляет форму без культуры, сорта или года посадки
- **THEN** для каждого незаполненного обязательного поля отображается понятная ошибка, а создание не выполняется

#### Scenario: Некорректные количество или год

- **WHEN** пользователь вводит количество 0 либо год посадки в будущем
- **THEN** отображается понятная ошибка, а создание не выполняется

#### Scenario: Некорректная длина пользовательского названия

- **WHEN** пользователь вводит заполненное название, которое после очистки крайних пробелов короче 3 или длиннее 200 символов
- **THEN** отображается понятная ошибка, а создание не выполняется

### Requirement: Успешное создание посадки

После успешного сохранения приложение SHALL возвращать пользователя на `/plots/:plotId` участка; новая посадка SHALL отображаться в секции своей категории, а счётчик категории SHALL увеличиваться без полной перезагрузки страницы.

#### Scenario: Создание с корректными данными

- **WHEN** пользователь выбирает культуру и сорт, указывает год посадки и подтверждает создание
- **THEN** посадка сохраняется, а на экране участка появляется её строка в соответствующей секции с обновлённым счётчиком

#### Scenario: Сохранение ещё выполняется

- **WHEN** запрос создания ещё не завершён
- **THEN** повторная отправка формы недоступна, чтобы не создать дубликаты

### Requirement: Отмена и ошибка создания посадки

Пользователь SHALL иметь возможность отменить создание и вернуться на экран участка без новой посадки. При ошибке сохранения форма SHALL показывать понятное сообщение и сохранять введённые значения.

#### Scenario: Отмена создания

- **WHEN** пользователь отменяет создание
- **THEN** он возвращается на `/plots/:plotId`, а посадка не добавляется

#### Scenario: Репозиторий отклонил создание

- **WHEN** сохранение завершилось ошибкой
- **THEN** форма остаётся заполненной и показывает понятное сообщение без изменения состава участка

### Requirement: Форма для неизвестного участка

При открытии формы с несуществующим участком приложение SHALL показывать понятное состояние «участок не найден» вместо формы и MUST NOT создавать посадки для несуществующего участка.

#### Scenario: Добавление в несуществующий участок

- **WHEN** пользователь открывает `/plots/unknown/plants/new`
- **THEN** отображается сообщение об отсутствии участка, а форма недоступна

### Requirement: Мобильное представление формы посадки

Содержимое формы SHALL помещаться без горизонтальной прокрутки на ширине 390 px и MUST NOT использовать emoji; необходимая инфографика SHALL использовать иконки MDI.

#### Scenario: Мобильный экран формы

- **WHEN** пользователь открывает форму добавления посадки на ширине 390 px
- **THEN** все поля и кнопки читаются без горизонтальной прокрутки

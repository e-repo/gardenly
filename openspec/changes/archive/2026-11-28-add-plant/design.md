# Design

## Context

Планируется строго после `plot-details`: детальный экран участка, аккордеон категорий со сводкой счётчиков, постраничная выдача посадок и категории `Culture.category` уже существуют. Мотивация и объём — в [proposal.md](proposal.md), требования — в `specs/`. Форма создания участка (`PlotCreateForm.vue`, метод `createPlot` в store) служит образцом сценария: те же паттерны валидации, блокировки submit, отмены и ошибок.

## Goals / Non-Goals

**Goals:**

- Завершённый сценарий «экран участка → форма → посадка в своей категории аккордеона» без неработающих controls.
- Проверки посадки на уровне контракта репозитория, а не только в форме.
- Обновление счётчиков и списков детального экрана без полной перезагрузки.

**Non-Goals:**

- Не добавлять фото посадки, собственные культуры вне каталога, редактирование и удаление (`edit-plant`).
- Не менять постраничный контракт чтения посадок и набор категорий культур.
- Не сохранять созданные посадки между полными перезагрузками.

## Decisions

### Контракт создания посадки

В `app/domain/garden.ts` добавляются:

```ts
interface NewPlantInput {
  plotId: string;
  cultureId: string;
  variety: string;
  plantedYear: number;
  locationNote?: string;
  quantity?: number;
  customName?: string;
}

createPlant(input: NewPlantInput): Promise<Plant>;
```

`MockGardenRepository` хранит рабочий список посадок в памяти экземпляра (по аналогии с участками): исходный JSON переезжает в изменяемое поле, все чтения продолжают возвращать `structuredClone`-снимки. `createPlant()`:

- проверяет существование участка и культуры, обязательные непустой сорт из `commonVarieties` и целый `plantedYear <= текущего года`, а также целое `quantity >= 1` (по умолчанию 1);
- после `trim()` отклоняет заполненный `customName` короче 3 или длиннее 200 символов; пустой `customName` преобразует в `undefined`;
- выполняет `trim()` строковых полей;
- создаёт человекочитаемый mock-ID через монотонный счётчик экземпляра (`plant-N`), как `createPlot`;
- проставляет `createdAt` текущим моментом, усечённым до секунд по RFC 3339 (конституция §9);
- добавляет посадку и возвращает независимый snapshot.

Сводка категорий и постраничная выдача считаются по рабочему списку, поэтому новая посадка появляется в них автоматически; отдельных изменений в этих методах не требуется.

### Форма и store

Форма — новый компонент `app/modules/plots/plant-create/components/PlantCreateForm.vue`: `v-combobox` не используется (он допускает произвольные значения); культура — обязательный `v-autocomplete` по каталогу с поиском по названию, сорт — обязательный `v-select` по `commonVarieties` выбранной культуры, заблокирован до выбора культуры. Год посадки — обязательное числовое поле с верхней границей текущего года, количество — числовое поле с минимумом 1 и значением по умолчанию 1. Отправка без сорта или года, а также с заполненным названием вне диапазона 3–200 символов после `trim()` показывает локальные ошибки и не вызывает store. Компонент фичи владеет загрузкой участка и каталога, состояниями загрузки/not-found и отправкой; страница только компонует экран.

Метод `createPlant(input)` добавляется в существующий store деталей (`app/modules/plots/plot-details/store.ts`): форма работает в контексте открытого участка, и именно этот store владеет составом. При успехе store локально обновляет состояние: инвалидирует загруженные страницы категории новой посадки (следующее раскрытие секции перечитывает её с первой страницы) и увеличивает счётчик в `categorySummaries` — так соблюдается постраничный контракт без локальной вставки в середину отсортированных страниц.

Открытие формы для неизвестного участка: страница формы запрашивает `getPlot(plotId)` и при `null` показывает состояние «участок не найден» вместо формы — то же представление, что и на детальном экране.

### Маршрут и возврат

`app/pages/plots/[plotId]/plants/new.vue` — только композиция: заголовок и `<PlantCreateForm />`. Детальный экран переносится из `app/pages/plots/[plotId].vue` в `app/pages/plots/[plotId]/index.vue`: иначе Nuxt вкладывает форму в родительский маршрут и без `<NuxtPage />` продолжает показывать детали. После успеха выполняется `router.push(`/plots/${plotId}`)`; отмена возвращает туда же без вызова репозитория. Кнопка «Добавить растение» появляется в `app/modules/plots/plot-details/components/PlotDetailsContent.vue` под аккордеоном (и в пустом состоянии состава) и ведёт на маршрут формы.

### Тестирование

- Repository-тесты `createPlant`: успех с обязательными и полными полями, нормализация пробелов, значения по умолчанию, отклонение каждого нарушения (участок, культура, отсутствующий или недопустимый сорт, отсутствующий или недопустимый год, количество, название вне диапазона 3–200 символов) без изменения состояния, границы названия 2/3/200/201 символ и пустое значение, видимость в сводке и постраничной выдаче, независимость snapshot.
- Store-тесты: успешное создание обновляет счётчик и инвалидирует страницы категории, ошибка сохраняет состояние экрана, повторная отправка заблокирована во время запроса.
- Компонентные тесты: поиск культуры, блокировка сорта до выбора культуры и его список из `commonVarieties`, ошибки незаполненных культуры, сорта и года, ошибки длины названия с границами 2/3/200/201 символ и допустимое пустое значение, остальные ошибки валидации, блокировка submit, успех с возвратом и новой посадкой в секции, отмена, сохранение введённых значений при ошибке, состояние неизвестного участка, отсутствие emoji; кнопка «Добавить растение» на детальном экране и в пустом состоянии.

## Risks / Trade-offs

- [Созданная посадка исчезает после полной перезагрузки] → Известное ограничение mock-этапа; постоянное хранение появится с backend без смены сценария UI.
- [Инвалидация страниц категории перечитывает её заново] → Одна страница по умолчанию (10 посадок) локального mock — стоимость пренебрежима, а сортировка страниц остаётся консистентной без локальных вставок.
- [Сорт строго из списка ограничивает редкие сорта] → Осознанное решение для консистентности данных; расширение каталога и пользовательские сорта — отдельные changes.

## Migration Plan

1. Применить и заархивировать `plot-details` (категории, аккордеон, `getPlot`).
2. Добавить `NewPlantInput` и `createPlant` с repository-тестами.
3. Расширить store деталей методом создания и обновлением счётчиков.
4. Собрать форму, маршрут и точки входа на детальном экране.
5. Прогнать quality gates и выполнить Chrome-сценарий: `/garden` → «Дача» → «Добавить растение» → создать посадку → увидеть её в секции с обновлённым счётчиком; отмена и ошибки формы; форма для несуществующего участка.

Откат удаляет форму, кнопки и метод создания; созданные в памяти посадки исчезают при перезапуске и не требуют миграции данных.

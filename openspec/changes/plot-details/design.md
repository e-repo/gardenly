# Design

## Context

После `garden-plots-overview` репозиторий уже предоставляет посадки участка (`getPlantsByPlot`), каталог культур (`getCultures`) и погоду (`getCurrentWeather`), но не умеет читать один участок по идентификатору. Карточки на `/garden` намеренно некликабельны, а детального маршрута нет. Мотивация и объём — в [proposal.md](proposal.md), требования — в `specs/`. Ограничения оформления и архитектуры — в `openspec/constitution.md`.

## Goals / Non-Goals

**Goals:**

- Завершённый сценарий «список участков → состав конкретного участка» без неработающих controls.
- Состав посадок в аккордеоне категорий с ленивой постраничной загрузкой, готовой к большим участкам и будущему backend без смены UI.
- Чтение одного участка через контракт репозитория, пригодный для будущей HTTP-реализации.
- Декомпозиция детального экрана по принятому в модуле паттерну состояний (тонкий переключатель + компоненты состояний).

**Non-Goals:**

- Не добавлять редактирование и удаление посадки, кнопки добавления растения, истории ухода и перехода к отдельной посадке — их экраны принадлежат инкрементам `add-plant`, `care-history` и последующему изменению редактирования.
- Не менять предметные типы `Plant` и связи сущностей; меняется только множество значений `Culture.category`.
- Не сохранять какое-либо состояние между полными перезагрузками.

## Decisions

### Чтение участка: `getPlot(plotId)` вместо фильтрации списка

В `GardenRepository` добавляется:

```ts
getPlot(id: string): Promise<Plot | null>;
```

Mock-реализация ищет в рабочем списке участков (включая созданные в этой сессии) и возвращает независимый snapshot либо `null`. Альтернатива — вызывать `getPlots()` и фильтровать на клиенте — отклонена: детальный экран не должен зависеть от полного списка, а точечное чтение ресурса по идентификатору соответствует AIP-стилю будущего HTTP API.

### Категории культур

`Culture.category` приводится к фиксированному справочному набору, согласованному с будущим backend-каталогом:

```ts
type CultureCategory = 'fruit-berry' | 'vegetable' | 'ornamental' | 'flower';
```

Это предметные идентификаторы, а не UI-группировка: категория живёт в данных каталога, её отображаемое название локализуется через i18n (`Плодовые и ягодные культуры`, `Огород`, `Лиственные и хвойные`, `Цветы`). Отдельная сущность «группа» не вводится — группы на экране являются проекцией категории.

Mock-каталог расширяется культурами всех категорий (добавляются томат, клён, роза; существующие яблоня, груша, вишня и смородина получают `fruit-berry`), а состав «Дачи» — посадками новых культур: Томат Бычье сердце 5 шт, Клён Гиннала 1 шт и Роза Фламентанц 3 шт. Категория `fruit-berry` намеренно раздута до 32 посадок: это даёт больше трёх страниц выдачи и позволяет вручную проверить автоподгрузку с лимитом и кнопку «Показать ещё» в браузере.

### Аккордеон вместо плитки

Секции категорий — вертикальный `v-expansion-panels` во всю ширину, а не плитка 2×2 из макета `docs/4.jpg`. Плитка требует выравнивания карточек с разным числом растений (equal-height ряды с пустотами либо обрезка контента) и тесна на 390 px. В аккордеоне свёрнутая секция — одна строка одинаковой высоты независимо от количества посадок, а раскрытая просто отодвигает нижние секции. Секции по умолчанию свёрнуты: это даёт ровный экран при любом составе и делает раскрытие естественным триггером загрузки.

Аккордеон работает в режиме single-expand (без `multiple`): открыта не более одной секции, поэтому нижние секции никогда не уезжают дальше одного развёрнутого списка — это стандартный ответ на проблему «как добраться до нижних пунктов гармошки» при длинных списках. При раскрытии секция прокручивается заголовком к верху, при сворачивании длинного списка скролл возвращается к её заголовку.

### Автоподгрузка страниц в секции

Внутри раскрытой секции вместо постоянной кнопки «Показать ещё» работает `v-infinite-scroll` (событие `@load`): следующая страница подгружается при приближении прокрутки к концу списка. Автоподгрузка ограничена тремя страницами подряд (~30 посадок), дальше появляется кнопка «Показать ещё» — гибрид защищает от «пробега мимо», когда пользователь просто прокручивает длинную секцию к нижним, и при этом убирает кнопку в подавляющем большинстве реальных случаев. Лимит — презентационная константа UI и в контракт репозитория не попадает; счётчик лимита сбрасывается при каждом раскрытии секции, иначе автоподгрузка при повторных раскрытиях накапливала бы лимит без реальной прокрутки и кнопка появлялась бы преждевременно.

### Контракт посадок: сводка категорий и постраничная выдача

`getPlantsByPlot` заменяется двумя методами, чтобы экран не тянул все посадки участка сразу:

```ts
interface PlantCategorySummary {
  category: CultureCategory;
  count: number;
}

interface PlantsPage {
  plants: Plant[];
  nextPageToken?: string;
}

getPlantCategorySummaries(plotId: string): Promise<PlantCategorySummary[]>;
getPlantsByPlotCategory(
  plotId: string,
  category: CultureCategory,
  page?: { pageSize?: number; pageToken?: string },
): Promise<PlantsPage>;
```

Сводка — лёгкий запрос, дающий заголовки секций и счётчики до загрузки самих посадок. Выдача постраничная по AIP-158: `pageSize` по умолчанию 10, `pageToken` непрозрачен для клиента. Сортировка фиксируется сразу, иначе страницы «плывут»: по названию культуры, затем по `id` посадки. Mock-реализация выполняет ту же нарезку в памяти, токен — строковое смещение; префетч первых страниц всех категорий в будущем — просто вызов того же метода без изменения контракта.

### Store деталей как отдельный setup-store модуля `plots`

Новый `app/modules/plots/plot-details-store.ts` со состоянием: `plot`, `categorySummaries`, `cultureById`, `weather`, `isLoading`, `hasLoadError` и по категории — `plants`, `nextPageToken`, `isLoading`, `hasLoadError`, `loaded`. Отдельный store, а не расширение существующего `plots`-store: состояния экранов независимы, ошибка деталей не должна скрывать список сада и наоборот. Текущий маршрут в store не дублируется — `loadPlotDetails(plotId)` принимает идентификатор аргументом.

Первичная загрузка выполняет параллельно `getPlot`, `getPlantCategorySummaries`, `getCultures`, `getCurrentWeather` и присваивает результат целиком после всех ответов — частичное содержимое не показывается (тот же приём, что в `loadGarden`). Состояние «участок не найден» определяется по `plot === null` при успешном чтении: остальные запросы для неизвестного id по контракту возвращают пустые значения и не мешают. Ошибка любого запроса переводит экран в состояние ошибки.

`loadCategory(category)` вызывается при первом раскрытии секции (повторное раскрытие использует уже загруженные страницы), `loadMorePlants(category)` — действием «Показать ещё» и дописывает страницу в конец. Состояние секции локально: её загрузка и ошибка не переводят весь экран в соответствующие состояния.

Культуры материализуются в `cultureById: Record<string, Culture>`; строка посадки получает готовую культуру и не делает lookup сама. Отсутствующая культура в каталоге — невозможная для текущих моков ситуация; поведение при ней не специфицируется и не маскируется.

### Компоненты и маршрут

- `app/pages/plots/[plotId].vue` — только композиция: заголовок раздела не нужен, страница рендерит `<PlotDetails />`.
- `PlotDetails.vue` — читает `plotId` из route, запускает загрузку в `onMounted` и переключает состояния: `<PlotDetailsLoading v-if>`, `<PlotDetailsLoadError v-else-if>`, `<PlotNotFound v-else-if>`, `<PlotDetailsContent v-else>`. Паттерн повторяет `GardenOverview` без computed-мапы `<component :is>`: цепочка `v-if/v-else` читается линейно и не конфликтует со строгими type-aware правилами линтера.
- `PlotDetailsContent.vue` — шапка (возврат на `/garden` иконкой `mdi-arrow-left`, название, локация, погода с fallback) и аккордеон категорий; пустой состав показывает локализованное сообщение вместо секций.
- Состав рендерится через `v-expansion-panels` (single-expand, по умолчанию свёрнут): по одной панели на категорию из сводки в фиксированном порядке `fruit-berry → vegetable → ornamental → flower`. Заголовок панели — MDI-иконка категории, локализованное название и количество посадок из сводки. Тело панели — индикатор загрузки, сообщение об ошибке либо список посадок с `v-infinite-scroll` и кнопкой «Показать ещё» после лимита автоподгрузки, пока есть `nextPageToken`. Состояние сворачивания локально для экрана и не сохраняется.
- `PlantListItem.vue` — одна посадка внутри панели: название культуры с сортом, количество, возраст и место одной читаемой строкой, как в макете («Яблоня Антоновка · 8 лет · 1 шт · у забора»). Необязательные поля рендерятся только при наличии значения.

### Иконки категорий и форматирование

`app/modules/plots/plants.ts` — явное отображение `Culture.category` в MDI-иконки: `fruit-berry` → `mdi-food-apple-outline`, `vegetable` → `mdi-carrot`, `ornamental` → `mdi-pine-tree`, `flower` → `mdi-flower-outline` (по аналогии с `weather.ts`); предметные типы и mock-данные иконок не содержат. Там же — фиксированный порядок категорий.

Возраст вычисляется как `текущий год − plantedYear` на клиенте и форматируется plural-строкой vue-i18n с формами русской локали («1 год / 2 года / 5 лет»). Количество — `{n} шт.`. Все строки — через `app/i18n/locales/ru.json`, секция `pages.plotDetails`.

### Карточка участка становится переходом

`PlotCard.vue` получает `:to="`/plots/${plot.id}`"` на `v-card`; оформление (тонкая рамка `teal-lighten-3`, скругление 4px, hover-elevation) не меняется. Возврат с детального экрана — обычная навигация роутера, поэтому аппаратная кнопка «назад» на Android работает через историю без дополнительного кода.

### Тестирование

- Repository-тесты `getPlot`: существующий участок совпадает со списком, неизвестный id → `null`, независимость snapshot, участок, созданный через `createPlot`, читается по id.
- Repository-тесты каталога и состава: все категории культур из нового набора, каталог покрывает четыре категории, исходный состав «Дачи» содержит семь посадок всех категорий.
- Repository-тесты сводки и постраничной выдачи: счётчики совпадают с фактическим числом посадок, пустая сводка для «Дома» и неизвестного участка; первая страница в стабильном порядке, продолжение по токену без повторов и пропусков, пустая страница без токена для пустой категории и неизвестного участка. Прежние тесты `getPlantsByPlot` переписываются на новый контракт.
- Store-тесты: успешная первичная загрузка (plot, summaries, cultureById, weather), участок без посадок, `null`-участок → not-found без ошибки, отказ любого из четырёх запросов → ошибка без частичного состояния; ленивая загрузка категории один раз, дописывание страницы в конец, ошибка секции не трогает экран.
- Компонентные тесты: переключение состояний, секции в фиксированном порядке со счётчиками и свёрнутые по умолчанию, single-expand (раскрытие сворачивает прежнюю секцию), загрузка при раскрытии, автоподгрузка до лимита и кнопка «Показать ещё» после него, отсутствие подгрузки без продолжения, ошибка секции, атрибуты посадки, отсутствие необязательных полей без заглушек, пустой состав, возврат на `/garden`, отсутствие emoji и неподдерживаемых controls; `PlotCard` ведёт на `/plots/:plotId`.

## Risks / Trade-offs

- [Прямой заход на `/plots/:plotId` грузит четыре запроса вместо одного] → Запросы параллельны и локальны на mock-этапе; batch-метод добавляется только при реальной необходимости.
- [Созданный в сессии участок доступен на детальном экране только до перезагрузки] → Известное ограничение mock-этапа, зафиксировано ещё в `plots-data-foundation`; постоянное хранение появится с backend без смены сценария.
- [Замена значений `Culture.category` ломает прежних потребителей] → Категория пока нигде не используется вне каталога (проверяется поиском); моки и тесты обновляются в том же change.
- [Замена `getPlantsByPlot` ломает существующие тесты] → Метод не используется в UI (проверяется поиском), repository-тесты переписываются на новый контракт в том же change.
- [Порядок страниц «плывёт» при изменении данных между запросами] → Сортировка стабильна (культура, затем id); mock-этап не меняет данные между страницами, а backend-реализация унаследует тот же критерий.
- [Склонение возраста зависит от plural-правил vue-i18n] → Форматирование вынесено в модуль и проверяется unit-тестами для форм 1/2/5; при переходе на английский словарь расширяется отдельным change.

## Migration Plan

1. Обновить категории `Culture.category`, mock-каталог и состав «Дачи» с repository-тестами.
2. Заменить `getPlantsByPlot` на сводку категорий и постраничную выдачу, добавить `getPlot`, обновить repository-тесты.
3. Добавить store деталей, `plants.ts` (иконки и порядок категорий) и ключи i18n.
4. Собрать компоненты детального экрана и страницу `/plots/[plotId]`.
5. Сделать `PlotCard` переходом и обновить его тесты.
6. Обновить `docs/personal-agronom-mvp.md`: иерархию данных с категориями (§4) и описание экрана участка аккордеоном (§6.3).
7. Прогнать quality gates и выполнить Chrome-сценарий: открыть `/garden`, перейти в «Дачу», увидеть четыре свёрнутые секции со счётчиками, раскрыть секцию и увидеть посадки, свернуть обратно, вернуться назад; открыть несуществующий id и увидеть состояние «не найден».

Откат — возврат некликабельных карточек и удаление новых файлов; миграции данных нет.

# Spec Delta

## MODIFIED Requirements

### Requirement: Исходный состав сада

Mock-реализация SHALL возвращать исходные посадки участка «Дача», покрывающие все категории культур. Категория `fruit-berry` SHALL содержать 32 посадки — достаточно для проверки постраничной выдачи и автоподгрузки; остальные категории SHALL содержать минимум по одной посадке: Томат Бычье сердце, Клён Гиннала и Роза Фламентанц. Каждая посадка SHALL иметь обязательный `plotId` участка «Дача»; репозиторий SHALL позволять получить посадку по идентификатору.

#### Scenario: Чтение исходного сада

- **WHEN** потребитель последовательно вычитывает посадки участка «Дача» по всем категориям
- **THEN** возвращаются исходные посадки с культурой, возрастом, местом, количеством и `plotId` участка «Дача»: 32 посадки категории `fruit-berry` и минимум по одной посадке в каждой из остальных категорий

#### Scenario: Поиск существующего растения

- **WHEN** потребитель запрашивает посадку по известному идентификатору
- **THEN** возвращается соответствующая посадка с обязательным `plotId`

#### Scenario: Поиск отсутствующего растения

- **WHEN** потребитель запрашивает посадку по неизвестному идентификатору
- **THEN** возвращается `null`, а ошибка не выбрасывается

### Requirement: Общий каталог культур

Культуры SHALL оставаться общими справочными данными и MUST NOT принадлежать отдельному участку. Одна культура может использоваться посадками разных участков. Категория культуры SHALL быть одной из фиксированного справочного набора: `fruit-berry` (плодовые и ягодные культуры), `vegetable` (огород), `ornamental` (лиственные и хвойные), `flower` (цветы). Каталог SHALL содержать культуры всех четырёх категорий; отображаемые названия категорий локализуются на стороне UI и в данных не хранятся.

#### Scenario: Использование культуры на разных участках

- **WHEN** на двух участках есть посадки одной культуры
- **THEN** их записи имеют разные `id` и `plotId`, но могут ссылаться на один `cultureId`

#### Scenario: Чтение каталога

- **WHEN** потребитель запрашивает культуры
- **THEN** каждая культура имеет категорию из фиксированного набора, и все четыре категории представлены в каталоге

### Requirement: Посадки конкретного участка

Каждая посадка SHALL принадлежать ровно одному участку через обязательный `plotId`. Репозиторий SHALL возвращать посадки запрошенного участка постранично по одной категории культур за запрос: ответ содержит страницу посадок и, когда есть продолжение, токен следующей страницы. Порядок SHALL быть стабильным между запросами: по названию культуры, затем по идентификатору посадки.

#### Scenario: Чтение состава участка

- **WHEN** потребитель последовательно вычитывает все страницы посадок всех категорий существующего участка
- **THEN** вместе они содержат все и только те посадки, у которых `plotId` совпадает с идентификатором участка

#### Scenario: Участок без посадок или неизвестный участок

- **WHEN** потребитель запрашивает страницу посадок любой категории участка «Дом» или неизвестного участка
- **THEN** возвращается пустая страница без посадок других участков

#### Scenario: Чтение первой страницы категории

- **WHEN** потребитель запрашивает первую страницу посадок категории существующего участка
- **THEN** возвращаются посадки только этой категории и этого участка в стабильном порядке, с токеном следующей страницы, если посадок больше размера страницы

#### Scenario: Чтение следующей страницы

- **WHEN** потребитель запрашивает страницу по полученному токену
- **THEN** возвращаются следующие посадки той же категории без повторов и пропусков относительно предыдущих страниц

#### Scenario: Категория без посадок или неизвестный участок

- **WHEN** потребитель запрашивает посадки категории без посадок либо неизвестного участка
- **THEN** возвращается пустая страница без токена продолжения и без посадок других участков

## ADDED Requirements

### Requirement: Сводка категорий участка

Репозиторий SHALL предоставлять по участку сводку непустых категорий посадок с количеством посадок в каждой, без загрузки самих посадок. Для участка без посадок или неизвестного участка SHALL возвращаться пустая сводка.

#### Scenario: Чтение сводки

- **WHEN** потребитель запрашивает сводку категорий участка «Дача»
- **THEN** возвращаются все категории, в которых у участка есть посадки, с их точным количеством

#### Scenario: Сводка участка без посадок

- **WHEN** потребитель запрашивает сводку участка «Дом» или неизвестного участка
- **THEN** возвращается пустая сводка

### Requirement: Чтение одного участка

Репозиторий SHALL предоставлять участок по идентификатору. Для неизвестного идентификатора SHALL возвращаться `null`, а ошибка MUST NOT выбрасываться. Возвращённый участок SHALL быть независимым снимком: его изменение потребителем MUST NOT влиять на результаты последующих вызовов.

#### Scenario: Поиск существующего участка

- **WHEN** потребитель запрашивает участок по известному идентификатору
- **THEN** возвращается участок с теми же названием и локацией, что и в списке участков

#### Scenario: Поиск отсутствующего участка

- **WHEN** потребитель запрашивает участок по неизвестному идентификатору
- **THEN** возвращается `null`, а ошибка не выбрасывается

#### Scenario: Потребитель изменил полученный участок

- **WHEN** потребитель изменяет полученный объект участка и повторно запрашивает его
- **THEN** повторный результат содержит исходные значения

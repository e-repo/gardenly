# garden-data-access Specification

## Purpose
Предоставляет экранам единый доступ к согласованным локальным данным сада через контракт репозитория, скрывая источник данных и сохраняя возможность последующей замены реализации.

## Requirements

### Requirement: Доступ через репозиторий

Приложение SHALL предоставлять потребителям данные сада через `GardenRepository`; UI MUST NOT импортировать mock-реализацию или файлы мок-данных напрямую.

#### Scenario: Потребителю нужен состав сада

- **WHEN** модуль запрашивает растения через внедрённый `GardenRepository`
- **THEN** он получает предметные объекты без импорта реализации из `data/`

### Requirement: Исходный состав сада

Mock-реализация SHALL возвращать четыре исходных растения: Яблоня Антоновка, Груша Лада, Вишня Молодёжная и Смородина чёрная, а также позволять получить растение по идентификатору.

#### Scenario: Чтение исходного сада

- **WHEN** потребитель запрашивает список растений
- **THEN** возвращаются все четыре исходных растения с культурой, возрастом, местом и количеством

#### Scenario: Поиск существующего растения

- **WHEN** потребитель запрашивает растение по известному идентификатору
- **THEN** возвращается соответствующее растение

#### Scenario: Поиск отсутствующего растения

- **WHEN** потребитель запрашивает растение по неизвестному идентификатору
- **THEN** возвращается `null`, а ошибка не выбрасывается

### Requirement: Задачи на текущий день

Mock-реализация SHALL возвращать невыполненные задачи с целевой локальной датой сегодня и задачи, выполненные сегодня, независимо от календарной даты запуска.

#### Scenario: Запуск в произвольную локальную дату

- **WHEN** потребитель запрашивает задачи дня
- **THEN** возвращаются предусмотренные мок-сценарии для этой даты без редактирования исходных мок-данных

#### Scenario: Задача не относится к текущему дню

- **WHEN** невыполненная задача имеет целевую дату раньше или позже сегодняшней и не была выполнена сегодня
- **THEN** она не входит в результат задач текущего дня

### Requirement: Содержание задач и связь с растениями

Каждая задача SHALL содержать растение, тип, название, причину, инструкции, целевую дату и статус; репозиторий SHALL возвращать задачи конкретного растения.

#### Scenario: Чтение задачи для объяснения рекомендации

- **WHEN** потребитель получает задачу дня
- **THEN** у неё есть данные для блоков «Почему сейчас» и «Как сделать»

#### Scenario: Чтение задач растения

- **WHEN** потребитель запрашивает задачи по идентификатору растения
- **THEN** возвращаются только задачи, связанные с этим растением

### Requirement: Справочные данные первых экранов

Репозиторий SHALL предоставлять справочник культур, настройки с регионом «Подмосковье» и статичные мок-данные погоды для экрана «Сегодня».

#### Scenario: Чтение справочника и настроек

- **WHEN** потребитель запрашивает культуры и настройки
- **THEN** доступны исходные культуры четырёх растений и регион «Подмосковье»

#### Scenario: Чтение мок-прогноза

- **WHEN** потребитель запрашивает погоду текущего дня
- **THEN** возвращаются статичные состояние и температура без сетевого запроса

### Requirement: Моменты времени в API

Моменты времени SHALL передаваться JSON-строками RFC 3339 в UTC с точностью до секунд в формате `YYYY-MM-DDTHH:mm:ssZ`. Дробные секунды, смещения часового пояса и Unix timestamp MUST NOT использоваться; при сериализации дробная часть усекается, а не округляется.

#### Scenario: Передача момента выполнения задачи

- **WHEN** backend или frontend сериализует `completedAt`
- **THEN** значение имеет вид `2026-05-10T06:30:00Z`, без дробных секунд и локального смещения

### Requirement: Календарные даты в API

`dueDate` SHALL передаваться в формате `YYYY-MM-DD` без времени и часового пояса и MUST NOT преобразовываться в UTC-момент.

#### Scenario: Передача целевой даты задачи

- **WHEN** backend или frontend передаёт `dueDate`
- **THEN** значение имеет вид `2026-05-10` и сохраняет тот же календарный день независимо от часового пояса пользователя

### Requirement: Часовой пояс локального дня

При серверном вычислении локального дня система SHALL использовать отдельно переданный часовой пояс пользователя в формате IANA.

#### Scenario: Сервер определяет задачи на сегодня

- **WHEN** backend вычисляет текущий локальный день пользователя
- **THEN** он использует отдельно переданную IANA timezone, а не календарную дату UTC и не время из `dueDate`

### Requirement: Независимые read-only snapshots

Результаты mock-реализации SHALL быть независимыми снимками: изменение возвращённого объекта потребителем MUST NOT изменять результаты последующих вызовов.

#### Scenario: Потребитель изменил полученный объект

- **WHEN** потребитель изменяет объект из одного результата и повторно запрашивает те же данные
- **THEN** повторный результат содержит исходные значения

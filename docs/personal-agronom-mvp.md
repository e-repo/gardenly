# ТЗ: «Персональный агроном» — MVP (Версия 1)

**Статус:** черновик для разработки фронтенд-прототипа
**Дата:** ноябрь 2026

---

## 1. Концепция продукта

Мобильное приложение для садоводов-любителей, отвечающее на один вопрос:

> **Что мне нужно сделать с моим садом сегодня?**

Приложение знает состав сада пользователя, регион, сезон и (в перспективе) погоду — и формирует персональный список задач на день. Это не энциклопедия растений и не календарь, а персональный помощник.

**Главная ценность MVP:** пользователь открывает приложение утром и сразу видит, что делать сегодня и почему.

---

## 2. Технический стек

| Слой             | Технология                                       |
| ---------------- | ------------------------------------------------ |
| Фреймворк        | Nuxt 4 (Vue 3, `<script setup>`, TypeScript)     |
| Режим рендеринга | SPA (`ssr: false`)                               |
| UI-кит           | Vuetify 3 (Material Design)                      |
| Состояние        | Pinia                                            |
| Нативная обёртка | Capacitor (Android; iOS — позже)                 |
| Данные (этап 1)  | Mock-repository поверх локального JSON           |
| Данные (этап 2)  | Http-repository → Supabase / Go API + PostgreSQL |

### Ключевое архитектурное требование

UI не обращается к данным напрямую. Все данные — через интерфейс репозитория:

```text
UI (страницы, компоненты)
    ↓
GardenRepository (интерфейс)
    ↓
MockGardenRepository   ← этап 1, локальный JSON
HttpGardenRepository   ← этап 2, замена без правок UI
```

## 4. Детальное описание экранов

### 01. Сегодня (Today) — главный экран

**Цель:** ответить «что делать сегодня» за 5 секунд после открытия.

**Содержимое (сверху вниз):**

1. Шапка: дата («Сегодня · 18 апреля»), регион, иконка погоды (в MVP — статичные мок-данные).
2. Блок «🔥 Важно» (0–2 карточки): срочные рекомендации с объяснением причины.
   - Пример: «Обработать яблоню — до дождя осталось 2 дня».
   - Карточка визуально выделена (акцентный цвет/бордер).
3. Блок «🌱 Задачи на сегодня»: список чекбокс-задач.
   - Элемент: эмодзи/иконка культуры, название задачи, растение.
   - Тап по чекбоксу → задача выполнена (анимация, переход в «Выполнено», запись в историю).
   - Тап по строке → экран 04.
4. Блок «✓ Выполнено сегодня»: свёрнутый список выполненных задач.
5. Пустое состояние: «На сегодня задач нет — сад в порядке 🌿».

**Действия:** выполнить задачу; перейти в задачу; перейти в сад.

**Переходы:** → 04 (тап по задаче), → 02 (bottom nav).

---

### 02. Мой сад (Garden)

**Цель:** показать состав сада, дать точку входа к растениям и добавлению.

**Содержимое:**

1. Заголовок «Мой сад», счётчик растений.
2. Список растений — карточки: эмодзи культуры, название («Яблоня Антоновка»), возраст, место («у забора»), 1 строка статуса («есть задачи на сегодня» / «всё в порядке»).
3. FAB или кнопка «+ Добавить растение» → экран 05.
4. Пустое состояние (первый запуск): иллюстрация-заглушка + CTA «Добавьте первое растение».

**Действия:** перейти к растению; добавить растение.

**Переходы:** → 03 (тап по карточке), → 05 (кнопка).

---

### 03. Карточка растения (Plant)

**Цель:** всё о конкретном растении + его ближайшие работы.

**Содержимое:**

1. Шапка: фото-заглушка/эмодзи, название, сорт, возраст, место, дата посадки.
2. Блок «Активные задачи»: список задач этого растения (тот же компонент, что на экране 01).
3. Блок «Скоро»: 2–3 предстоящие работы с датами («Обрезка — начало марта»).
4. Кнопки действий: «История ухода» → 06; «Диагностика по фото» → 07.
5. Кнопка «Редактировать» (иконка) → переиспользование формы экрана 05.

**Переходы:** → 04, → 06, → 07, назад → 02.

---

### 04. Карточка задачи (Task)

**Цель:** объяснить ЧТО сделать, ЗАЧЕМ и ПОЧЕМУ именно сейчас — это главный продуктовый экран.

**Содержимое:**

1. Заголовок задачи («Обрезать яблоню»), растение, дедлайн-период («в течение 3 дней»).
2. Блок «Почему сейчас»: текст-объяснение причины (фаза развития, температура, прогноз).
   - В MVP текст берётся из мок-данных, но поле модели проектируется сразу — это будущий вывод rules engine.
3. Блок «Как сделать»: 3–5 коротких шагов-инструкций.
4. Блок «Важно» (опционально): предупреждение («через 2 дня похолодание»).
5. Основная кнопка «Выполнить» → отметка выполнения + возврат на предыдущий экран.
6. Вторичные действия: «Отложить» (перенос на завтра), «Не актуально» (скрыть).

**Переходы:** назад → 01 или 03; после выполнения — назад с обновлённым состоянием.

---

### 05. Добавить растение (Add Plant)

**Цель:** добавить растение за ≤60 секунд. Форма по шагам (stepper) или один скролл — на усмотрение реализации, главное минимум обязательных полей.

**Поля:**

| Поле                  | Тип                                                                                    | Обязательность |
| --------------------- | -------------------------------------------------------------------------------------- | -------------- |
| Культура              | Выбор из справочника (поиск + эмодзи): яблоня, груша, вишня, слива, смородина, малина… | Обязательно    |
| Сорт                  | Текст с автоподсказками по культуре                                                    | Необязательно  |
| Возраст / год посадки | Число или год                                                                          | Необязательно  |
| Место в саду          | Короткий текст («у забора», «ряд 2»)                                                   | Необязательно  |
| Количество            | Число (по умолчанию 1)                                                                 | Необязательно  |
| Свое название         | Текст («Яблоня у калитки»)                                                             | Необязательно  |

**Поведение после сохранения:** растение появляется в саду, для него генерируются задачи (в MVP — из мок-правил по культуре и текущей дате), переход на экран 03 нового растения с подтверждением «Растение добавлено, появились задачи ухода».

**Переходы:** сохранить → 03; отмена → назад.

---

### 06. История ухода (History) — P1

**Цель:** журнал всех работ по растению — зародыш «цифрового паспорта сада».

**Содержимое:** хронологическая лента (новые сверху) событий: выполненные задачи, ручные записи, фото. Элемент ленты: дата, тип события (иконка), описание. Фильтр по типу (все / обработки / подкормки / обрезка / заметки).

**Действия:** добавить запись вручную (текст + опционально фото).

---

### 07. Фото / диагностика (Photo) — P1, заглушка

**Цель:** зарезервировать место под ИИ-диагностику, проверить интерес пользователей.

**Содержимое:** кнопка «Сфотографировать» (через Capacitor Camera — сохраняет фото в историю растения), блок «Анализ появится в следующих версиях». Никакой ИИ-логики в MVP.

---

### 08. Настройки (Settings) — P1

**Содержимое:** регион (выбор из списка — влияет на мок-генерацию задач), уведомления (время утреннего напоминания, вкл/выкл), единицы измерения, «О приложении», сброс данных (для разработки).

## 5. Модели данных

```typescript
// Растение в саду пользователя
interface Plant {
  id: string;
  cultureId: string; // ссылка на справочник культур
  variety?: string; // сорт
  customName?: string; // "Яблоня у калитки"
  plantedYear?: number;
  locationNote?: string; // "у забора"
  quantity: number;
  photoUrl?: string;
  createdAt: string;
}

// Справочник культур (предзаполнен)
interface Culture {
  id: string; // "apple", "pear", "cherry"...
  name: string; // "Яблоня"
  emoji: string; // "🍎"
  category: 'tree' | 'bush' | 'berry' | 'flower';
  commonVarieties: string[];
}

// Задача ухода
interface Task {
  id: string;
  plantId: string;
  type:
    'pruning' | 'feeding' | 'treatment' | 'watering' | 'inspection' | 'other';
  title: string; // "Обрезать яблоню"
  reason: string; // "Почему сейчас" — ключевое поле продукта
  instructions: string[]; // шаги "Как сделать"
  warning?: string; // "Через 2 дня похолодание"
  dueDate: string; // целевая дата
  dueWindow: number; // допустимое окно в днях (±)
  status: 'pending' | 'done' | 'skipped' | 'postponed';
  completedAt?: string;
}

// Событие истории ухода
interface CareEvent {
  id: string;
  plantId: string;
  taskId?: string; // если событие порождено задачей
  type: string;
  note?: string;
  photoUrl?: string;
  createdAt: string;
}

// Настройки / профиль
interface Settings {
  region: string; // "Подмосковье" и т.п.
  notificationsEnabled: boolean;
  notificationTime: string; // "08:00"
}
```

## 6. Интерфейс репозитория

```typescript
interface GardenRepository {
  // Сад
  getPlants(): Promise<Plant[]>;
  getPlant(id: string): Promise<Plant | null>;
  addPlant(input: NewPlantInput): Promise<Plant>;
  updatePlant(id: string, patch: Partial<Plant>): Promise<void>;
  removePlant(id: string): Promise<void>;

  // Задачи
  getTodayTasks(): Promise<Task[]>;
  getTasksByPlant(plantId: string): Promise<Task[]>;
  completeTask(taskId: string): Promise<void>;
  postponeTask(taskId: string, days: number): Promise<void>;
  skipTask(taskId: string): Promise<void>;

  // История
  getHistory(plantId: string): Promise<CareEvent[]>;
  addCareEvent(input: NewCareEventInput): Promise<CareEvent>;

  // Справочник и настройки
  getCultures(): Promise<Culture[]>;
  getSettings(): Promise<Settings>;
  updateSettings(patch: Partial<Settings>): Promise<void>;
}
```

**Mock-реализация:** данные в `src/data/*.json` + генератор задач: по культуре и текущей дате выдаёт правдоподобные сезонные задачи (захардкоженные правила вида «яблоня + апрель → обработка, обрезка»). Состояние (выполненные задачи) — в Pinia + persist в localStorage, чтобы переживало перезапуск.

**Мок-сад по умолчанию** (при первом запуске, чтобы прототип сразу выглядел живым): Яблоня Антоновка (8 лет), Груша Лада (5 лет), Вишня Молодёжная (6 лет), Смородина чёрная (3 года). Регион: Подмосковье.

## 7. Нефункциональные требования

- **Mobile-first:** вёрстка под ~390px ширину, touch-таргеты ≥ 44px, без зависимости от hover.
- **Анимации:** только `transform` и `opacity`; переходы между экранами через Vue `<Transition>`; ripple и стандартные анимации Vuetify.
- **Производительность:** время до интерактивности на среднем Android < 3 с.
- **Офлайн:** этап 1 работает полностью офлайн (данные локальные) — это свойство mock-архитектуры, сохранить.
- **Android-специфика:** аппаратная кнопка «назад» ведёт по истории роутера (`@capacitor/app`); отступы под safe area; splash screen и иконка — минимальный брендинг.
- **Язык UI:** русский.

## 8. Границы MVP (что НЕ входит)

- Регистрация, аккаунты, синхронизация между устройствами.
- Реальный бэкенд и API.
- Интеграция с погодным API (в моках — статичный «прогноз»).
- ИИ-консультант и реальная диагностика по фото.
- Push-уведомления (настройки экрана 08 — задел на будущее).
- Геймификация (уровни, достижения).
- iOS и десктоп-вёрстка (адаптив до планшета — по остаточному принципу).

---

## 9. Критерий готовности MVP

Прототип готов, если по нему проходят два сценария без тупиков и перезагрузок:

1. **«Утро на даче»:** открыть приложение → увидеть задачи дня и блок «Важно» → открыть задачу → прочитать «почему сейчас» и «как сделать» → выполнить → задача ушла в «Выполнено» и в историю растения.
2. **«Новое растение»:** Сад → «+ Добавить» → выбрать культуру, ввести сорт → растение в списке → у него есть задачи на сегодня/скоро.

Плюс: APK собирается и стабильно работает на реальном Android-устройстве.

Оценки ориентировочные и предполагают небольшие отдельные changes с проверками качества.
